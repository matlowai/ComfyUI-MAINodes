# Conversation pilot: source review and revised acceptance gates

Review baseline: `e80f220`, on `snap-research-2026-11-08`. This follow-up checks the external review against the actual checkout. It updates plans; it does not implement the fixes, launch native permission tests or qualify production use. Qualitative review scores are opinions, not measurements.

The accepted architecture remains unchanged: durable conversation/session service, external agent adapter, existing MCP/WebMCP creative tools, independent director notes and explicit continuity. Keep the parent R0–R8 DAG in [conversation status](CONVERSATION_STATUS_2026-11-09.md).

## Findings and evidence

| Finding | Assessment | Evidence and limit |
|---|---|---|
| Command approval can lack its operation | Confirmed P0 defect | `request_card` offers Allow once when `command` is absent; an isolated actual-function probe also showed `request_response` accepts that approval. Both display and outbound-response validation need guards. The shared outbound helper likewise accepts a file-change decision without establishing a diff, even though its file card correctly withholds the button. No real command or file change was executed. |
| Pre-attachment messages become invisible to delivery | Confirmed P0 defect | An isolated adapter-loop probe retained a human message in history, excluded it through `initial`, advanced the cursor and made no delivery call. This matches first-attachment logic; no live backlog was replayed. |
| Messages queued during an existing adapter outage can also strand | Additional confirmed P0 defect | Even when a message is after the original binding and is not in `initial`, startup `replay` advances the cursor past it. The loop only submits newly returned events. The isolated probe made zero delivery calls for this case too. The fix must reconstruct a pending worklist, not merely remove the `initial` exclusion. |
| Pending native approval recovery | Confirmed implementation/qualification gap | Requests are transport-local in `Attachment.requests`; history replay reconstructs human messages and delivery receipts, not native pending request handles. Epoch refusal protects against stale approvals but does not recover a waiting request. Actual runtime-origin reconnect remains untested. |
| Conversation project identity is contextual rather than an enforced write guard | Confirmed boundary gap; live wrong-project mutation not demonstrated | The adapter gives the model an instruction and project context. Bridge page selection and optional `if_revision` checks are useful foundations, but no mandatory conversation-bound project/page check was found on mutation execution. Journal account/project isolation tests do not establish this execution property. |
| Streaming repeatedly rebuilds history and DOM | Source behavior confirmed; performance impact unmeasured | `projectEvents` scans event history on each snapshot; Room serializes its projection/activity and rebuilds messages/activity DOM with `replaceChildren`. Repeated deltas can grow cost and reset mounted detail state. No latency, memory or long-session benchmark is claimed. |
| Composer footer can retain waiting wording after delivery | Confirmed UI state issue | Send sets a fixed saved/waiting string; per-message receipts change later but do not drive that footer. It is misleading presentation, not evidence that delivery failed. |

Source owners: [adapter](../../tools/snap_chat.py), [service](../../snap_conversations.py), [bridge](../../snap_bridge.py), [tool dispatch](../../web/snap/tools.js), [Room](../../web/snap/room.js), [journal client](../../web/snap/conversation.mjs), [projection](../../web/snap/conversation_state.mjs). Local private repro artifacts retain the exact fake-provider inputs/results; published source remains the reproducible basis. Prior successful idle/active chat and refresh/restart evidence is retained; these findings limit it rather than erase it.

## R1: explicit P0 subnodes

Each node records inputs, outputs/owned files, dependencies, status and acceptance. They are planning nodes, not authorization to launch a runtime, experiment, installer or destructive fixture gate. Shared adapter/Room/service files are serialized; no parallel writes are inferred from this table.

| Node | Inputs → outputs / owned files | Blocked by | Status | Acceptance |
|---|---|---|---|---|
| R1A: exact-operation approval | Native request kind, item/turn identity and actual operation → adapter `request_card` / `request_response`, service request contract, focused tests | R0 | confirmed defect; ready to implement when selected | Resolve the exact command and working directory from the matching native request/item, or offer no executable acceptance. Preserve Decline where supported. Distinguish command, stdin, network and file actions; do not substitute a parent command for another operation. Missing/wrong/stale item cases cannot be approved through UI, HTTP or adapter responses. Extend the existing file-card diff requirement to outbound acceptance too. |
| R1B: first-attachment backlog disposition | Undelivered messages, destination session and explicit human choice → service journal, adapter startup/delivery selection, Room pending-message controls, focused tests | R0 | confirmed defect; ready to implement when selected | Show Send pending to this agent / Keep as history, including which messages and destination. Persist disposition and stable ids; no silent initial replay, stranded waiting state or duplicate send after restart. Historical-only and uncertain messages never become new instructions automatically. |
| R1C: enforce project/page identity for mutations | Conversation/session ownership, intended page/project and existing revision mechanisms → existing bridge, tool dispatch, applicable MCP/snapcall metadata and proposal/execution owners | R0 | source boundary gap; ready for focused owner audit | Conversation-owned mutations carry a required expected project/page association, checked at the actual mutation/queue boundary including delayed operations and proposal acceptance. A changed/missing target refuses before graph/file/queue mutation; no fallback to the newest eligible page. Read/navigation and deliberate rebinding remain explicit. Use existing native owners, not a second permission engine. State the guarantee for native Snap mutations, not arbitrary shell actions outside that channel. |
| R1D: reconcile pending native requests | R1A request representation, R1C identity and durable pending/resolution state → adapter, service, Room and focused reconnect tests | R1A, R1C | incomplete implementation; native qualification pending | Reconcile the runtime's actual outstanding request/turn on reconnect before accepting an answer. Handle provider/CLI resolution, cancellation, expired handles and a lost answer acknowledgement without stale permission or duplicate execution. If a runtime cannot reattach/reissue a request, show a blocked/expired state and supported recovery instead of inventing a handle. Keep runtime approval and native creative approval distinct. |
| R1G: combined live acceptance gate | Completed guards, backlog handling and request recovery; retained session evidence → scoped integration receipts and status updates | R1A, R1B, R1C, R1D, R2A | pending; not launched by this review | Attach to an existing session, resolve backlog choice, send idle/active, stream, review the exact operation, allow/decline, disconnect/reconnect and recover once. Repeat with immediate project switch and pending approval during disconnect; prove unchanged wrong-target graph/files/queue and original-conversation replies. Do not lower inherited policies to manufacture human approval; use an appropriate dedicated fixture or report the native path unqualified. |

Recommended serial order: exact-operation guard (R1A), mutation-boundary audit/guard (R1C), explicit initial-backlog disposition plus outage reconstruction (R1B/R2A), pending native request recovery (R1D), then R1G. This retains R1/R2/R3 ahead of ACP without folding every improvement into one implementation commit.

## R2: recovery and UI subnodes

| Node | Inputs → outputs / owned files | Blocked by | Status | Acceptance |
|---|---|---|---|---|
| R2A / P0: pending worklist after outage | Durable message/disposition/receipt state and original binding → adapter replay/worklist, service event semantics, restart/duplicate tests | R0 | confirmed additional defect | Reconstruct undelivered messages already assigned to the same adapter from journal state independently of the subscription cursor. Recover outage-queued input; never retry uncertain runtime acceptance or repeat completed/kept-as-history messages. Survive crashes before/after delivery intent and acknowledgement. |
| R2B / P1: incremental rendering | Existing normalized event ids, transcript and activity → client/projection and keyed Room updates, controlled measurements | R0 | source concern confirmed; performance unmeasured | Update affected messages/activity without remounting unrelated transcript rows or the composer. Preserve scroll anchor, selection, focused request input and expanded details. Measure a declared long-history/delta fixture before/after; preserve complete history through explicit paging if needed, never silent truncation. |
| R2C / P2: receipt-driven status text | Latest submitted message id, project identity and disposition/receipt → Room footer/status helper and UI checks | R1B, R2A | confirmed wording defect | Footer distinguishes saved, awaiting destination choice, sending, delivered, complete, uncertain and kept history from actual journal state. A late receipt cannot overwrite the status/draft of a newer send or another project. |

Existing R2 storage, single-writer/concurrency, corrupt-tail, backup and long-session gates remain open. R3 session picker/startup/Stop lifecycle follows supported permissions and recovery. R4 ACP, R5 linked notes, R6 handoffs and R7 multimodal work remain in the parent DAG.

## Scope corrections

This feature did not modify the creative registry at `e80f220`, and this review did not measure progressive tool discovery or token efficiency. Keep that optimization project separate. No architecture redesign is justified by these findings; the immediate work is concrete correctness guards and recovery at current owners.
