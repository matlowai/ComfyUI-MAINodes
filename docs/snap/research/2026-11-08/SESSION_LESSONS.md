## Paired Snap dogfood — 2026-11-09

Current implementation and qualification: [paired workspace status](../../PAIRED_WORKSPACE_STATUS_2026-11-09.md). These are lessons from actual paired use, isolated reproductions and the subsequent fixes; they are not a claim that the full integration gate passed.

- **Keep the human's main goal through support detours.** The sprite/character brief was a quick real-world test of the paired Snap workflow. Once the person receiving help is helped, return to the stated paired-UX goal. Recover the original human request when a handoff's accumulated chronology obscures that distinction; put current focus before historical entries.
- **Keep project context visible and choices inspectable.** A translucent movable/resizable Conversation/Decisions/Results workspace worked better for the paired session than an opaque fullscreen approval flow. Show recorded dependencies, but allow free inspection. Short dial names and explicit endpoints beat repeated prompt paragraphs or technical rack-binding language.
- **Saving a message is not waking an agent.** The earlier note-only composer persisted a native note with a separately visible reply; wake-up was unfinished at that milestone. The later connected-conversation pilot adds actual delivery receipts and streaming; saved, delivered and completed remain distinct. Preserve the user's submitted trial snapshot rather than substituting controls edited later.
- **Async completion must not erase newer intent.** Unconditional composer clearing after save/approval lost newer typing in an isolated reproduction. Bind clearing to the submitted draft revision/project, freeze the original decision reason and preserve failed-save retry identity. Switching workflows must retain each workflow's draft.
- **Cached controls need a recipe owner.** A result card cached by dial filename reused obsolete duration/curve settings. Preserve intentional trial edits while the recipe is unchanged; refresh an unedited stale card, or keep edited controls visibly stale and require explicit reload before applying them. Preserve existing curve interpolation, time units, steps and audio behavior.
- **Use generic defaults and explicit action presets.** Constant steering is the unconfigured starting point; an existing rack curve remains an existing curve. The punch/wind-up/release idea belongs to an explicit preset or action-specific proposal, not every blur, lighting or style dial. Label curve shape as relative level and the scalar as strength/peak; a denoising envelope is not clip time.
- **Verify what an opened/copied shot will actually execute.** A copied-shot request fell back to a starter recipe during one probe. Inspect the actual loaded prompt, references, seed, size, processing state and executed rack before queueing each comparison. Preserve invalid attempts separately; successful jobs with the wrong input are not valid experimental conditions.
- **Treat stage 1 and stage 2 as distinct outputs.** Stage 1 was computed but only the final de-roped clip was saved. A CreateVideo intermediate is not a named persisted file; ComfyUI's execution history is not an intermediate-video archive. Check saved outputs/cache evidence before regenerating, and do not promise export-only recovery without a guard that refuses sampling on cache misses. Saving both stages remains a native workflow improvement to build.
- **Read actual execution/cache evidence.** De-rope selection is the branch choice; zero second-pass steps can mean automatic scheduling, not disabled de-rope. Runtime node events established four-step second passes in the tested Oracle runs. Later raw exports had stage-1 cache misses and resampled under explicit authorization. A graph's configured nodes or a count of executed nodes alone do not prove the desired stage ran or was retained.
- **A strong direction is not isolated control.** Extreme crisp/soft scores changed identity, framing, costume, timing and style; motion cues could become drawn trails, dust or painterly rendering rather than smooth local blur. Pair agreement measures construction consistency. A shared opening image kept design closer in one 0/−6 pair, but poses/timing still changed; do not call that pure edge control or a universal strength range.
- **References change the experiment.** Hold the exact reference, prompt, seed, strength and processing settings within a comparison. First-frame-conditioned and text-only tests are different pipelines; a reference can constrain motion. A lossless extracted frame remains its native resolution, not newly invented detail. A trained adapter remains a hypothesis, not an automatic prerequisite.
- **Live previews and result previews have different owners.** Sampling frames need job/node/graph metadata and URL cleanup; saved takes need their own output identity. Old node snapshots are not current sampling. Oversized saved-video autoplay can destabilize control; preserve manual playback. Software Chrome rendering is a local opt-in fallback, not an unmeasured universal default.
- **Readiness must match supported artifacts.** RelayVSR preflight incorrectly required full-precision weights when a supported quantized pair was installed. Reuse the backend's quant/VRAM resolution logic, keep missing runtime versus missing weights distinct, and test without loading a model.
- **Separate validation layers.** Actual-handler/module tests caught draft/state regressions, while a real screenshot caught an SVG still visible in constant mode. Use the application's Python environment for its dependencies. Verify named test cases rather than assuming a file-level test-runner pass exercised them. Pure CPU, visible UI, native execution, full integration gate, audio measurements and human perceptual approval remain different evidence. The dedicated gate is still pending.
- **Preserve and integrate useful sidebar fixes deliberately.** Keep scoped commits for paired UX, readiness and browser fallback; do not sweep unrelated cleanup notes into them. Minimal dial publication used only the artifact, original pairs and short usage notes after the user excluded videos. Preserve negative results and exact provenance locally; publication size is the user's choice.


## Connected conversation architecture — 2026-11-09

[Current evidence and remaining work](../../CONVERSATION_STATUS_2026-11-09.md) · [adapter/service contract](../../CONVERSATION_ADAPTERS.md). These are local-pilot results, not full release qualification.

- **Conversation, creative tools and continuity have different owners.** Preserve the existing MCP/WebMCP creative registry. Normal chat belongs to a durable backend journal independent of graph undo; director notes remain annotations, and active instructions change only through their existing explicit owner.
- **A service must outlive the view.** Stream agent text/activity into the journal directly, including unsolicited output. An open browser or a per-reply MCP call must not own conversation durability. Preserve send-time project/artifact context even when the person changes views.
- **Discovering a session is not controlling it.** A read-only probe established identity; actual active Send, subsequent idle Send, streamed reply and reconnect supplied stronger evidence. Keep live attachment, saved-session resume and cross-provider handoff distinct. Another provider’s session-load capability does not establish hot attachment.
- **A receipt must survive uncertainty.** Persist stable send identity/intent before invoking a runtime. A repeated browser save can reuse its journal id; uncertain runtime acceptance must not be blindly retried. Keep human direction, delivery acknowledgement, completed reply and execution/creative approvals separate.
- **Native permission paths need native evidence.** Synthetic HTTP approval tests and schema mappings do not prove a real runtime request or pending-approval reconnect. Tie responses to the current controller epoch and preserve stale/external resolution; never lower the inherited policy to manufacture a passing test.
- **Backend replay and UI readiness are separate.** An early diagnostic import poisoned ComfyUI’s compatibility module before initialization. A normal reload and readiness-guarded probe restored the page; the durable journal was intact. Wait for the real UI before importing compatibility modules in diagnostics.
- **Keep the UI ordinary.** Preserve people’s text and full agent answers; put command payloads and activity details behind expandable controls. Expose connection/delivery state without turning the Room into a runtime dashboard.
- **Write down the supported boundary.** The current lease covers one Snap service/account, not every independent native client or multiple server processes sharing storage. Record unqualified concurrency, long-session, startup, accessibility and native request cases before calling a pilot a universal workspace.
